# My Deck 需求拆分與工時估算

- 文件版本：V0.1
- 本次範圍：只拆分 **REQ-001「開放註冊、登入與角色識別」**
- 需求依據：`docs/requirements.md` V0.4、`docs/permissions.md` V0.1
- 估算口徑：每項工時均包含該互動所需的設計、開發、自測及調整；不包含其他 REQ，也不代表整個項目總工時
- 拆分狀態：REQ-001 已完成首輪拆分，待使用者檢查；REQ-002 至 REQ-018 尚未拆分

## 1. 本次交付邊界

### 1.1 本次包含

1. 未登入使用者進入註冊頁。
2. 選擇手機號碼或電子郵件作為註冊識別。
3. 選擇老師或學生角色。
4. 提交合法資料、建立帳號及保存角色。
5. 必填、格式、密碼強度及帳號唯一性校驗。
6. 註冊失敗回饋、安全重試及防止重複提交。
7. 使用手機號碼或電子郵件和密碼登入。
8. 登入成功後依角色進入老師或學生首頁。
9. 有效登入狀態恢復、登入失效處理及跨角色存取拒絕。

### 1.2 本次不包含

- 管理員公開註冊、建立管理員或管理其他帳號；相關規則仍待確認。
- 驗證碼登入、手機或電郵驗證碼註冊；目前僅作擴充預留。
- 批量建立帳號；目前僅作擴充預留。
- 忘記密碼、重設密碼、第三方登入、單一登入及裝置管理；現有需求尚未提出。
- 註冊後修改角色或由管理員指定角色；現有需求尚未確認。

- 本總計未加入額外緩衝工時，也未包含其他需求、整體整合測試、部署及項目管理工時。
- TASK-004 與 TASK-005 的最終成功導向應在原型階段統一；兩者不能出現一個自動登入、另一個要求重新登入的不一致流程。

## 4. 跨任務資料與安全要求

1. 帳號至少綁定一個手機號碼或電子郵件；本期每次註冊使用其中一種識別方式。
2. 手機號碼及電子郵件分別執行唯一性校驗；服務端資料約束是最終防線，不能只做前端檢查。
3. 角色以服務端帳號記錄為準，不接受登入後由前端自行聲明或切換角色。
4. 密碼強度、密碼散列、工作階段保存及失效策略採用市場通用安全方案，具體參數須在安全設計中列明且可配置。
5. 註冊、登入及恢復工作階段的請求不得把密碼寫入日誌、網址參數或瀏覽器持久化儲存。
6. 所有必填、格式、唯一性、角色及工作階段校驗均須在服務端再次執行。
7. Edge 和 Chrome 的實際驗收版本須在後續測試方案中記錄；本拆分不預設未確認的版本號。
