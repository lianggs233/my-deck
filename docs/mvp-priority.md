## 1. MVP 目標與已確認假設

- 時間盒：6 天，以完成可示範 MVP 為目標。
- 使用者指定的最少能力：登入／註冊、課程展示、標籤功能。
- 「標籤功能」已確認指 **PPT 個人文字標註**；不是課程分類標籤。
- 已加入課程的學生可在本人課程頁預覽轉換成功的課件，並管理本人個人文字標註；此為已批准的非課堂例外，不要求建立即時課堂。
- REQ-006～REQ-008 即時課堂維持 P1；MVP 不做即時翻頁同步、訪客加入或重連。
- 註冊擁有者驗證碼（發送、校驗、重發及註冊驗證頁，TASK-020～TASK-025）移至後續優化（2026-11-18 確認）；本期註冊採免驗證碼流程，校驗通過後直接建立帳號、不自動登入，註冊後返回登入頁；已實作的後端註冊驗證碼端點保留不動，供後續優化啟用；忘記密碼的擁有者驗證碼流程維持本期交付。
- REQ-003 完整學生加入課程流程暫緩；MVP 演示使用預先建立的老師、學生帳號及課程成員關係，但 API 契約保留。
- 標註只做個人文字 CRUD；不做共享標註、聚合、老師回覆或標註匯出。
- 課件只做單檔上傳、靜態轉換、成功預覽及必要失敗提示；不追求 100% 動畫、音訊、影片或版式還原。
- 本期不開發管理員後台；帳號及演示資料由初始化程序建立。

## 4. 6 天交付順序

1. 第 1 天：完成統一技術基礎與 REQ-001 登入／註冊主流程。
2. 第 2 天：完成 REQ-002 課程建立、課程列表及必要課程上下文。
3. 第 3～4 天：完成 REQ-004／REQ-005 的課件上傳、轉換及預覽最小閉環。
4. 第 5 天：完成 TASK-333 課程頁學生預覽入口，並串接 REQ-010 個人文字標註 CRUD。
5. 第 6 天：完成 MVP 端到端修正、演示資料、核心錯誤處理及驗收。
