## 1. MVP 目標與假設

- 時間盒：6 天，以完成可示範 MVP 為目標。
- 使用者明確要求的最少能力：登入／註冊、課程展示、標簽功能。
- 本文件暫按既有產品語境，將「標簽功能」理解為 **PPT 個人文字標註**；若實際指「課程分類標籤」，本優先級需要重排。
- MVP 不代表刪減完整需求；完整需求仍保留於 `docs/requirements.md` 與 `docs/breakdown.md`。

## 2. 優先級定義

| 優先級 | 定義 | 6 天處理方式 |
|---|---|---|
| P0 | 沒有它就不能完成使用者指定 MVP 演示目標 | 必須交付；若完整範圍逾時，須再切出 MVP-S 最小可交付切片 |
| P1 | 對完整產品重要，但不阻塞本次最小演示 | 6 天內有餘力才做，否則延期 |
| P2 | 不屬本次 6 天 MVP 承諾 | 本次不做，只在完整需求中保留 |

## 3. 建議優先級

| 優先級 | 需求／能力 | 範圍說明 |
|---|---|---|
| P0 | REQ-001 登入／註冊／登出 | 以老師、學生可註冊、登入、登出及維持工作階段為最小閉環；完整帳號安全與恢復能力仍屬完整需求 |
| P0 | REQ-002 課程建立與展示 | 老師可建立課程並查看本人課程；課程資訊足以支撐後續課件及標註演示 |
| P0 | REQ-003 學生加入課程的最小路徑 | 若演示需學生身份進入課程，必須保留課程碼加入的最小閉環；若只做單角色演示，可暫緩 |
| P0 | REQ-004 課件上傳 | 只保留單檔 `.ppt`／`.pptx` 上傳的最小可用路徑及必要校驗 |
| P0 | REQ-005 課件轉換與預覽 | 保留背景轉換、成功預覽及必要失敗提示；完整重試與相容性歷史可延期 |
| P0 | REQ-010 學生個人文字標註 | 保留本人文字標註 CRUD 的最小可用體驗，個人標註僅本人可見 |
| P0 | NFR-012～NFR-013 統一主題與 rem 規範 | 作為 MVP 各頁面的基礎視覺約束，避免後期返工 |
| P1 | REQ-006～REQ-009 即時課堂、加入、翻頁及重連 | 對完整互動教學核心重要，但嚴格最小 MVP 可先以非即時課件預覽承載標註演示 |
| P1 | REQ-011～REQ-013 共享標註、聚合回覆及管理 | 高價值互動，但不是使用者本次指定的最少功能 |
| P1 | NFR-001、NFR-003～NFR-008 主要非功能驗收 | 需在正式環境或完整驗收補足；MVP 至少不引入相悖實作 |
| P2 | REQ-014～REQ-016 簽到、答題及統計 | 本次 6 天 MVP 不承諾 |
| P2 | REQ-017～REQ-018 結束、摘要、保留、匯出及刪除 | 本次 6 天 MVP 不承諾 |
| P2 | 管理員詳細功能 | 本次 6 天 MVP 不承諾，且管理員詳細權限仍未定稿 |
| P2 | 動畫／音訊／影片完整還原、複雜版式與其他已列明排除項 | 本次 6 天 MVP 不承諾 |

## 4. 6 天交付順序建議

1. 第 1 天：完成統一技術基礎與 REQ-001 登入／註冊主流程。
2. 第 2 天：完成 REQ-002 課程建立、課程列表及必要課程上下文。
3. 第 3～4 天：完成 REQ-004／REQ-005 的課件上傳、轉換及預覽最小閉環。
4. 第 5 天：完成 REQ-010 個人文字標註 CRUD，並串接課件頁面。
5. 第 6 天：完成 MVP 端到端修正、演示資料、核心錯誤處理及驗收。

## 5. 工時風險

- 若按目前完整拆分，把 P0 相關的 REQ-001、REQ-002、REQ-004、REQ-005、REQ-010 及 NFR-012～NFR-013 全量計入，約 **163.5 小時**。
- 以 6 天 × 24 小時計，上限為 **144 小時**；完整 P0 已超出約 **19.5 小時**。
- 因此，6 天 MVP 不能直接承諾完整 P0；下一步須把 P0 再切成 **MVP-S 最小可交付切片**，明確暫緩的帳號、課程、轉換及標註邊界，並重新估算工時後取得確認。
