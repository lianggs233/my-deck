## 1. 切片目的與規則

本清單把 REQ-001～REQ-018 拆成可直接製作原型的具名頁面及交互切片，並建立 REQ、頁面與 TASK 的追蹤關係。本文件只整理介面結構，不新增或修改既有業務規則、權限及工時。

### 1.1 編號規則

| 編號 | 含義 | 原型製作方式 |
|---|---|---|
| `PG-###` | 可獨立進入、具有主要內容區的頁面 | 一個具名主畫板，可對應一個前端路由 |
| `OL-###` | 對話框、抽屜、彈出選單、面板或共用狀態層 | 獨立具名交互畫板或元件，不另設路由 |
| 頁面狀態 | 空白、載入、提交中、成功、失敗、無權限等 | 在所屬 PG／OL 下製作具名狀態，不另占頁面編號 |

- 每個 PG 及 OL 都有唯一、可直接顯示於設計稿名稱中的中文名稱。
- REQ、PG、OL、TASK 編號只用於文件及設計檔內部追蹤，**不在使用者可見的介面文案中顯示**。
- 同一頁面被多項需求使用時，只在首次出現的需求定義基礎結構；後續需求列出要增加的切片及狀態，避免重複建立頁面。
- 短暫的「載入中／重連中／提交中」等不是獨立路由頁面。
- 老師端以桌面為主要原型尺寸；學生及訪客頁須另檢查手機尺寸。所有頁面沿用 React + Mantine、Noto Sans TC、0.5rem 間距網格及既有色板。

### 1.2 數量摘要

- **20 個獨立頁面：**PG-001～PG-020。
- **28 個具名交互切片：**OL-001～OL-028。
- **合計 48 個具名設計切片。**各切片內的錯誤、空白及提交狀態另行列出，不計作新頁面。
- PG-001～PG-020 與 OL-001～OL-028 已全部輸出 Penpot；OL-001 另有老師／學生版本，加上兩個帳號狀態畫板，檔案共 51 個畫板。
- 已建立 14 條具名流程及 117 個交互；可見文字沒有需求或切片 ID，Penpot 檔案驗證沒有錯誤。

## 5. 共用狀態與角色差異

### 5.1 每個適用頁面都要檢查的狀態

1. **載入：**首次進入及重新整理，不只顯示空白畫面。
2. **空白：**無課程、無課件、無標註、無活動、零提交等，提供對應角色的下一步。
3. **失敗：**資料讀取、提交、下載及同步失敗，保留可行的重試或返回操作。
4. **提交中：**防止重複建立、重複簽到、重複作答、重複刪除及重複匯出。
5. **無權或身份失效：**不顯示越權資料，提供重新登入或安全返回。
6. **內容已變更：**他人已刪除、活動已結束、授權已收回、課堂已結束時，更新操作入口而不是繼續提交。
7. **響應式：**老師桌面、學生手機及訪客手機均須檢查文字溢出、固定面板及主要操作可達性。
